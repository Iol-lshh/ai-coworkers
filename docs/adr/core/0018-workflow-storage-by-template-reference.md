# ADR-0018: 실행은 슬롯을 템플릿 참조와 출구로 저장하고 템플릿 로그 스냅샷으로 복원함

- 상태: 수락됨
- 날짜: 2026-10-26

## 맥락

- 실행은 슬롯을 보유하고, 슬롯은 템플릿 객체를 보유함. [ADR-0004](0004-slot-holds-template.md)를 따름.
- 실행은 처음 실행하는 시점의 템플릿을 고정함. [ADR-0016](0016-workflow-snapshot-at-start.md)을 따름.
- 복원 경로는 저장된 식별자를 빌더에 그대로 넣음. [ADR-0003](0003-next-slot-by-factory.md)을 따름.
- 작업 템플릿은 저장 형태가 없음.

## 결정

- 워크플로우 틀은 템플릿과 같은 방식으로 저장함. [ADR-0015](0015-template-storage-and-optimistic-lock.md)를 따름.
- 실행은 식별자, 틀 식별자, 틀 버전, JSON 본문을 한 행에 저장함. 같은 식별자의 행이 있으면 본문을 갱신함.
- 본문은 슬롯, 사가, 합류 대기의 저장 형태를 담음. 변환은 [ADR-0014](0014-neutral-form-and-serd-module.md)를 따름.
- 슬롯의 저장 형태는 템플릿 식별자·버전과 출구 슬롯 식별자만 담음.
- 사가의 저장 형태는 상태와 노드의 식별자·상태·슬롯 식별자를 담음.
- 슬롯은 템플릿 로그에서 기록된 버전의 스냅샷을 찾아 빌더로 복원함.
- 작업 슬롯은 저장하지만 복원은 거부함.
- 사가 로그는 사가 식별자, JSON 스냅샷, 등록 시각을 한 행씩 추가함.

## 결과

- 템플릿 본문을 실행마다 중복 저장하지 않음.
- 기록된 버전의 템플릿 로그가 없으면 실행을 복원하지 못함.
- 작업 슬롯이 든 실행은 작업 템플릿의 저장 형태가 생겨야 복원할 수 있음.
- 실행 저장에는 낙관적 잠금이 없어, 같은 실행을 동시에 진행하면 나중 저장이 앞선 저장을 덮어씀.
